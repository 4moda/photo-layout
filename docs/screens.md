# 画面・状態・操作カタログ

PhotoLayout の全画面について、**画面の状態**と**操作のバリエーション**を網羅的に列挙する。
各画面に**画面ID**（`S01`…）、各機能に**機能ID**（`F01`…）を振り、スクリーンショットと
1:1で対応づける。実機を動かさずに、CIが撮る画像と本書だけで「どの画面のどの操作が
どう見えるか」を追えるようにするのが目的。

## スクリーンショットの命名規約と紐づけ

スクショ名（`AppTests/PhotoLayoutUITests/ScreenshotSmokeTests.swift` の `snapshot(...)`）は:

```
<画面ID>[-<機能ID>]-action-in-english
例: S01-F02-project-list-empty-state
    S02-single-photo-natural-placement
```

fastlane snapshot の出力ファイルは安全なASCII名の

```
<言語>/<端末slug>--<画面ID[-機能ID]-action-in-english>.png
例: ja-JP/iphone-16--S01-F02-project-list-empty-state.png
```

となる。`build_screenshot_index.py` はこの規約でファイル名を解析して `index.html` を生成する。したがって

| 軸 | 取得元 |
|---|---|
| 言語 | ディレクトリ名（`ja-JP` など） |
| 端末 | ファイル名の `--` より前（`iphone-16` など） |
| 画面ID / 機能ID | スナップ名の先頭トークン |

> **使う文字**: スナップ名はそのままPNGファイル名になるため、`A-Z a-z 0-9 -` のみを使う。
> 端末名も `SnapshotHelper.swift` 側で slug 化して保存する。

`AppTests/PhotoLayoutUITests/tools/build_screenshot_index.py` がこの規約でファイル名を解析し、
**言語・画面ID・端末で絞り込めて説明文で検索できる `index.html`** を生成する
（CIの `screenshots` artifact に同梱）。fastlane 標準の `screenshots.html` も併存する
（言語・端末のみの素朴な一覧）。

スクショ運用ツール一式（`fastlane/`・`tools/`）は撮影対象の UITest ターゲットと同じ
`AppTests/PhotoLayoutUITests/` 配下に置く。CIはこのディレクトリをCWDにして `fastlane snapshot`
を実行する（Snapfileのパスは `../../` でリポジトリ直下の xcodeproj / DerivedData を参照）。

## S01 プロジェクト一覧 (`ProjectListView`)

上部に「Recent」「Folder」のモード切替（手組みの2セグメント）を持つ。「Recent」は既存の全プロジェクトを更新日時順で表示するフラット一覧（本機能追加前と挙動は同じ）。「Folder」は作成済みフォルダの一覧で、フォルダをタップするとそのフォルダの`folderID`を持つプロジェクトだけを同じ`ProjectCell`/グリッドで表示する詳細画面へ遷移する（フォルダ未分類のプロジェクトは「Folder」モードには出ない）。フォルダセルはプロジェクトが1件以上あれば最新更新プロジェクトの1ページ目サムネイルをフォルダの枠に収めて表示し、右下に`ProjectCell`のページ数バッジと同じ見た目の「N件」バッジを重ねる（0件フォルダはフォルダアイコンのみでバッジなし）。フォルダ詳細画面にも下部フローティングの＋ボタンがあり、ここから新規作成したプロジェクトは最初からそのフォルダに属した状態で作られる。既存プロジェクトをあとからフォルダへ移動する操作は`ProjectCell`の「⋯」メニューの「フォルダへ移動」から行う。ピッカーは作成済みフォルダの一覧と「フォルダなし」（未分類に戻す）を並べ、現在の所属先には枠のハイライト＋チェックマークバッジを付ける。カード自体の見た目（アイコン＋下にキャプション、`systemGray5`の枠の正方形カード）はFolderモードのフォルダ一覧（`FolderCell`）と統一する。

### カバレッジ凡例と方針

各機能は次のいずれかで扱う:

- **✓ / スクショ名あり** — CIで自動撮影。index.html に載る。
- **ジェスチャ・撮影対象外**（S02-F17〜F26, S03-F10） — キャンバス直接操作。離散的な1枚の画像に馴染まないため、**結果状態**（配置後の見た目など）で間接的に確認する。
- **システムUI・撮影不可**（S02-F05 写真追加, S04-F02 カメラロール保存, S04-F05 共有） — PhotosPicker / 写真ライブラリ / 共有シートは別プロセス or 権限ダイアログのため、UIテストからの撮影は行わない。
- **アクション（遷移のみ）**（S03-F01/F02 キャンセル/完了, S04-F01 閉じる） — 固有の画面を持たないため撮らない（遷移先の画面で確認）。
- **ナビゲーション上到達不能**（S02-j 書き出し中スピナー） — `isExporting` は `PreviewView`（`.fullScreenCover` で全画面を覆う）の保存ボタン経由でしかtrueにならず、S02編集画面のツールバー自体は書き出し中は画面に出ない。実際に撮れる同等の状態はS04-c（`PreviewView`保存ボタンのスピナー）だが、こちらも非同期処理完了前の一瞬を捉える必要がありタイミング依存のため未着手。
- **タイミング依存・未着手**（S02-h スナップガイド） — ドラッグ中の一瞬だけ表示され、指を離すと同期的に消える（`endGesture()`）。標準のXCUITest APIでは確実に撮れず、バックグラウンドスレッドからの撮影など実装コストが見合わないため見送り。

この方針により「撮っていない＝抜け」ではなく、**撮らない理由が上のどれか**を各行で判別できる。

`--reset-store` はインメモリ・ストアで起動し、毎回空から始めることで状態を決定論的にする
（`AppComposition.container`）。デモ投入は `DemoProjectSeeder`。

新しい状態を撮りたいときは、対応するテストメソッドに `snapshot("<画面ID>[-<機能ID>]-action-in-english")`
を1行足すだけ。命名規約さえ守れば index.html のフィルタに自動で載る。
